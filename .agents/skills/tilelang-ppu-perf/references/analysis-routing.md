# 分析路由

目的：手上的数据该交给谁来解读、交接时该带什么。用错解读器比不解读更危险——用跨端口径看单端数据、用 bench 数字推机制，都会产出"看起来很有道理但无法复核"的结论。

本文只负责**路由与交接**。单端指标怎么读（SOL、停等分类、端内饱和判断）属于单端 skill 的职责，本文不复述，也不给替代版；而**跨端怎么对账**属于本 skill 内 [cross-end-analysis.md](cross-end-analysis.md) 的职责，本文只负责判定"能不能进跨端"。

## 1. 路由表

| 手上的东西 | 想问的问题 | 前置条件 | 去处 |
|---|---|---|---|
| 要采集 PPU 数据 | 命令该怎么写、开哪些开关 | **先调用 `acu-report-skill`** 确认开关与版本差异 | 本文定流程，`acu-report-skill` 定命令 |
| 要采集 NVIDIA 数据 | 同上 | **先调用 `ncu-report-skill`** | 本文定流程，`ncu-report-skill` 定命令 |
| 只有 PPU 报告（`.acurep`） | 指标含义、瓶颈、优化方向 | **先调用 `acu-report-skill`** | `acu-report-skill` |
| 只有 NVIDIA 报告（`.ncu-rep`） | 同上 | **先调用 `ncu-report-skill`** | `ncu-report-skill` |
| 两端报告都有 | 差在哪、为什么差、能否追平 | 两侧**各自**已完成单端分析（单端指标解读 + 停等分解 + 端内饱和判断），且 §4 门槛逐项通过；"两份文件都在"不是充分条件 | 本 skill 内 [cross-end-analysis.md](cross-end-analysis.md)（工作流、允许/禁止的对比方式与 SASS 速查都在这一页） |
| 只有 bench 数字，没有报告 | "为什么慢" | — | 先采集；不要从数字推机制 |
| 报告有但关键指标缺失 | 能不能硬下结论 | — | 不能：按 §6 降级，或重采（重采先问用户） |
| 只有宽表 CSV，没有报告本体 | 取数 | — | 可以取数；"为什么不饱和"这类问题必须回报告本体 |

单端 skill 负责"指标怎么读"，本文负责"数据可不可信"。两者冲突时以数据可信度优先：口径不正的数字，解读得再漂亮也是错的。

## 2. 交接时交的不只是报告路径

交给单端/跨端 skill 的最小交接包（通常就是归档 `README.md` + `manifest.json`）：

| 项 | 内容 |
|---|---|
| workload | kernel 语义名 + device 符号名、输入形状/规模 |
| launch | grid / block / shared_mem、实际 launch 次数、是否 graph replay |
| 版本 | profiler 版本、device/host 编译器版本、DSL 版本 + commit |
| 编译配置 | 优化级别、调试信息开关、目标 arch、关键宏、cache 是否 miss（真编译） |
| 产物位置 | 报告、宽表、逐指令导出、codegen 目录，以及"哪份报告对应哪个 codegen 目录" |
| 缺失项 | 未采的 set/section、降级项、被排除的 case 及原因 |
| 单位 | 表中 duration / bytes / pct 的单位来自哪里（导出来源，不是猜测） |

缺项就把它作为"已知未知"显式写出来，不要留给下一位去猜。

## 3. 路由前的最小自检（只判"能不能交出去"，不判指标含义）

| 问题 | 过不了就怎么办 |
|---|---|
| 报告能正常打开、行数符合 survey 结果？ | 回采集，见 [kernel-and-launch-selection.md](kernel-and-launch-selection.md) §5 |
| 宽表列名覆盖了要问的问题？ | page 或采集 set 没对上，见 [collection-and-export.md](collection-and-export.md) §4 |
| 知道这份报告对应哪个 kernel、哪个 config、哪份 codegen？ | 先补 README 与 manifest，否则交出去也无法解读 |
| 缺失项/降级项已写明？ | 先写声明再交，别让下游以为证据齐全 |
| 单位来源已登记？ | 未知就写"未知"，不要填默认值 |

## 4. 跨端对比的门槛

进入 [cross-end-analysis.md](cross-end-analysis.md) 之前，前置条件与可比性必须逐项通过。任一项不过就是"不可比"，不是"差不多可以比"。

**前置条件（比可比性更早）：两侧必须各自完成单端分析。** "报告存在"只证明采集完成，不证明有人读过它——进入跨端的最低要求是每一侧都已产出：瓶颈假设、停等分解、端内饱和判断（对照容量绝对值）。缺任一侧的单端结论，先回单端 skill 做完；在缺少单端结论时做跨端对账，等于拿两份没读懂的数据互相解释。

**可比性对账项**：

- 同一 kernel（符号级确认，不是"两个同名文件"）
- 输入形状与规模一致
- 访存 slot / 地址模式一致（对齐、padding、布局、是否 wram/vmem 直通）
- 工具版本、编译器版本、DSL 版本已知且已记录
- 实际 grid/block/shared_mem 一致
- 两侧的 stall 分解都已完成——否则"差在哪"只能答到现象层
- 两侧都有可用的绝对量计数（指令数、交易数、字节数、duration）——跨端只对账绝对量

后续工作流（Step 0 可比性 → Step 2 工作量对账 → Step 3 指令结构对等 → Step 4 停等对比 → Step 5 交易效率 → Step 6 端内饱和 → Step 7 闭环校验 → Step 8 归因输出）见 [cross-end-analysis.md](cross-end-analysis.md)。

三条最容易违反的纪律：

1. **百分比／SOL% 永不跨端相减**：两端峰值定义与锁频口径不同。只对账绝对量（时长、指令计数、交易计数、字节数）。
2. **可比性先确认**：不满足就先补控制变量，别用"应该差不多"凑。
3. **同名指标可能不同义**：按 metric id 对齐，不按显示名。

指标该按哪一列对齐、SOL 怎么算，由对应单端 skill 决定；本文只要求"对齐方式已记录、可复核"。

## 5. 口径类误判（只列与数据可信度/路由相关的几条）

指标含义层面的误判不在此列——单端语义见对应单端 skill，跨端的对账边界（停等类别、允许/禁止的对比方式）见 [cross-end-analysis.md](cross-end-analysis.md) §4。

| 误判 | 为什么错 | 正确做法 |
|---|---|---|
| 列数不同 → 数据缺 | 列数由采集 set 与工具版本决定 | 按列名取交集；缺的列去查采集命令 |
| 长表行数多 → launch 多 | 长表是"kernel × 指标" | 用宽表或 details 的 kernel 去重计数 |
| 两份报告都在 → 可以做跨端 | 单端解读与可比性都还没确认 | 先满足 §4 门槛 |
| 指标名相同 → 同一指标 | 不同工具/section 同名不同义（吞吐/访存类尤其常见） | 按 metric id 对齐 |
| 单位行不存在 → 单位是默认值 | 不同导出可能单位不同 | 查导出来源与 body 声明；仍未知就降级，**不按量级反推** |
| 派生指标与原始计数直接相加 | 派生指标已含换算，可能重复计入 | 只选一层，并在 README 注明选了哪层 |
| 报告打不开就以为是坏了 | 报告是二进制格式 | 用工具 CLI 或 API 导出，不能 `cat`/`grep` |

## 6. 证据强度与降级声明

| 级别 | 定义 | 例 |
|---|---|---|
| **实测** | 报告中的直接计数/比率 | duration、指令数、交易数、停等占比 |
| **推断** | 由实测值反推，或单边数据 + 容量反推 | 管线吞吐上限、由静态结构推的动态占比 |
| **假设** | 未经指标验证的机制解释 | "编译器应该会……" |

**必须降级的情形**：

- 采集 set 不全，关键 section 缺失 → 该维度结论最高只能到"推断"。
- per-PC / 逐指令 stall 为空 → 指令级归因降级，禁止据此定位到具体指令。
- 只有 bench 数字没有报告 → 只能给"现象"，不能给"机制"。
- 跨端结论默认在同级基础上降一档（工具口径不同）。**这不是例外，而是判据不同**：两侧绝对量直接计数完全吻合的对账结论（指令数 / 交易数 / 字节数绝对量相等）可维持"实测"——降档的理由是工具口径差异，而绝对量对账不依赖峰值与锁频口径，这条理由在这类结论上不成立。
- 单位或页来源不明 → 该数值只能当量级参考。

降级必须在报告里**显式写出来**，而不是悄悄给一个看起来很确定的结论。

## 7. 结论落地格式

每条结论至少带：

```
<结论一句话>
支撑：<文件名> / <列名> = <值>（单位）
对照：<另一侧或基线> / <列名> = <值>（单位）
强度：实测 | 推断 | 假设
边界：<该结论不成立的条件>
```

追不到"文件 + 列名 + 值"的结论，一律降级或删除。

## 8. 修正历史

推翻早先结论时，在报告头部保留修正链（第 N 版结论 → 被什么证据推翻 → 现结论），不要静默改写。修正链本身是分析可信度的一部分：它说明这个结论被真的验证过，而不是第一次就碰巧写对。
